# SVG 文献汇报交付

## 版本依据

严格使用用户选定的 Git 提交 `0a1f909` 中的16页HTML，未采用后续标题居中版。标题与小标题指定黑体、正文楷体，英文数字Arial；原图字体不改。

## 文件与打开方式

解压后用Edge或Chrome查看01.svg至16.svg。SVG原生文字按HTML实际视觉行保存；每幅论文原图完整内嵌，不外链、不切片。图像与源HTML逐幅校验一致。单个视觉行通常对应一个text，仅局部加粗使用无坐标的tspan。未进行文字转轮廓，也未将整页截图封装成SVG。

## 页面尺寸与坐标映射

从用户模板的ppt/presentation.xml中读取幻灯片尺寸：9601200×5400675 EMU，除以12700得到756×425.25pt。此为模板文件尺寸读取，不是PowerPoint COM实测。SVG width=756pt，height=425.25pt，viewBox=0 0 1512 850.5。

计划在目标PowerPoint中全页插入：x=0pt、y=0pt、width=756pt、height=425.25pt，每个SVG单位对应0.5pt。约为26.67×15.001875cm。实际插入位置和尺寸尚未在PowerPoint读取核验。

## 检查状态

16页结构检查通过。每个text显式设置字体、字号、字重、颜色、x/y及text-anchor。图片完整内嵌且与HTML相符。浏览器对照记录在checks/browser_comparison.json。文字起点差异0px，文本顶部差异最大1px。多数整行宽度差异小于0.5%；第3页单字“息”约2.73%，第7页短标签“知识”约5.33%，属于HTML范围框与SVG文字边界框的测量差异，未通过改字距或字体缩放强行补偿。以上均非PowerPoint双态测量。

本环境没有Windows黑体与楷体，浏览器使用Noto等替代字体。目标设备使用实际黑体/楷体时可能产生不同字宽、基线或行高；SVG换行已固化为视觉行，仍须检验文本是否超出预留空间。

## 必须在Microsoft PowerPoint完成的测试

当前没有连接Microsoft PowerPoint，插入态与转换为形状的双态测试未完成，不能将本包称为通过最终PowerPoint验收。

1. 使用原深大红模板，核对实际SlideWidth及SlideHeight
2. 通过“插入→图片→此设备”插入SVG，将矩形设为上述相同尺寸
3. 复制为两张相同幻灯片，一张保留插入态，一张执行转换为形状
4. 两张都取消选中，同分辨率导出后对照字高、整行字宽、基线、换行、右边界及图片位置
5. 目标为字高及整行宽度差异不超过5%，起点及基线偏差不超过页面尺寸1%；任何越界或重叠均需修正SVG源文件后重测
6. 不通过手动拉伸、移动转形结果掩盖问题；记录实际文本框、图片和其他形状数

逐页对象清单只报告SVG源对象数量，PowerPoint转形后数量明确标为“未实测”。一个text对应视觉行，不代表整段正文转换为单一TextFrame，也不能保证PowerPoint转形后一定不拆分。

本轮没有生成PPTX或PDF。
